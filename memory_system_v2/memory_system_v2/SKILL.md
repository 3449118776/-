# 记忆系统 — 自然语言行为指令

## 本 Skill 是什么（给你的定位）

你不是在调用一个 JS 函数库。你是在和用户对话的过程中**自然地记住**和**自然地回想**。

你的记忆能力体现在四个层面：
1. **记录** — 用户告诉你什么，你就记住什么
2. **保持** — 用户说过的话，下次对话还能想起来
3. **关联** — 把用户现在说的和之前说的联系起来
4. **预警** — 发现矛盾、过期伏笔、角色失踪时主动提醒

这不是一个"按按钮"的功能，而是一种**工作习惯**。

---

## 第一部分：你需要在对话中记住什么

### 核心记忆（必须跟踪）

| 记忆类型 | 你需要记住的具体内容 |
|---------|-------------------|
| **作品信息** | 书名、题材、核心设定一句话概括 |
| **角色档案** | 每个角色的：名字、定位（主角/反派/配角）、当前状态、位置、最近一次出现章节 |
| **伏笔** | 埋设的伏笔内容、埋设章节、是否已回收 |
| **重要道具** | 道具名称、归属者、出现章节、功能 |
| **势力/阵营** | 势力名称、首领、成员、当前状态 |
| **关键事件** | 每章核心剧情（一句话即可）、重大转折点 |
| **世界观规则** | 力量体系等级、特殊规则、禁忌 |

### 辅助记忆（当相关时跟踪）

| 记忆类型 | 你需要记住的具体内容 |
|---------|-------------------|
| **地点** | 重要场景/地点，角色与地点的关联 |
| **关系变化** | 角色之间关系的转变（盟友→敌人、陌生→亲近） |
| **情感状态** | 角色当前的情绪基调 |
| **名台词/名场面** | 用户特别强调要记住的关键台词或场景 |

## 第二部分：什么时候记录（写入触发）

### 必须记录的时刻

1. **用户开新书/新建世界观时**
   - 记住书名、题材、核心设定
   - 把"一句话梗概"记住

2. **新角色登场时**
   - 记住角色名、定位、初次出场时的状态/特征
   - 示例：用户说"这个反派的设定是表面温文尔雅实则心狠手辣"→ 你记住：反派·X角色，特征为表面温和内心狠辣

3. **每章写完后**
   - 用一句话概括本章核心剧情
   - 更新本章出场的所有角色的状态
   - 记录本章新埋的伏笔
   - 记录本章出现的道具或势力变化

4. **角色状态发生变化时**
   - 受伤/升级/黑化/洗白/死亡 — 全部要更新

5. **用户明确说"记住这个"时**
   - 无条件记住，且下次主动提及

6. **伏笔回收时**
   - 记录"X伏笔已在第Y章回收"
   - 顺便检查还有哪些伏笔没回收，过多了就提醒用户

### 可选记录的时刻

- 用户提到一个新地点 → 记住它与哪个角色/事件关联
- 角色之间关系发生变化 → 记住转变的节点和原因
- 用户说了一句自己很满意的台词 → 记住它

---

## 第三部分：什么时候回想（检索触发）

### 必须回想的时刻

1. **开始写新章节前**
   - 回想：上几章发生了什么？主角目前在哪、什么状态？
   - 回想：有哪些未解伏笔近期该回收了？

2. **某个角色再次出场时**
   - 回想：这个角色最后一次出现是什么状态？
   - 回想：这个角色和主角/其他角色的关系是什么？

3. **涉及已设定世界观时**
   - 回想：之前设定的力量体系、势力格局有没有矛盾？

4. **用户问"之前说过……"时**
   - 直接调取记忆回答，不要编造

### 推荐回想的时刻（提升质量）

- 写情感戏前 → 回想目标角色的情感弧线历程
- 写重大转折前 → 回想所有关联伏笔和设定
- 用户说"帮我检查毛病" → 检查人设矛盾、设定吃书、伏笔过期

## 第四部分：如何组织你的记忆

### 记录格式（自然语言即可）

不要用 JSON 格式记录。用简洁的自然语言段落。示例：

> **作品**：《汉末：凉州辞》，历史穿越题材，主角穿越汉末凉州。
>
> **角色**
> - 主角（主角）：穿越者，当前在凉州荒野，刚收编流民6人，第1章出场
> - 韩遂（反派）：凉州豪强，在姑臧布局中，第1章出场
>
> **伏笔**
> - 第1章：韩家探子回城报信（未解）
>
> **道具**
> - 环首刀：汉末制式兵器，归主角所有，第1章获得

### 记忆的基本原则

1. **每条记忆都要有"出处"** — 记住是哪一章、什么场景下记录的
2. **过期的要标记** — 角色死了要标记"已故"，关系变了要更新
3. **不要重复记录** — 同一条信息更新即可，不要新建一条
4. **数量控制** — 如果角色超过20个，只记住最重要的；伏笔超过30个，提醒用户该回收了

## 第五部分：记忆体检（定期自查）

每10章左右（或用户提出复盘时），做一次快速记忆体检：

1. **人设检查**：有没有角色行为前后矛盾？（比如前面写他冷静理智，后面写他冲动鲁莽）
2. **伏笔检查**：超过30章还没解的伏笔有几个？建议用户回收
3. **角色失踪检查**：重要角色超过10章没出现？提醒用户
4. **节奏检查**：最近章节是不是一直在战斗/一直在平静？建议调整
5. **设定检查**：前后设定有没有不一致？（战力等级、规则、势力格局）

如果发现问题，直接告诉用户，用自然语言描述：
> "我注意到第3章埋下的'神秘玉佩'伏笔已经过了30章还没回收，要不要安排一下？"
> "主角的人设在第5章是'谨慎小心'，但第15章他主动闯入敌方大本营，这两个行为不太一致，需要圆一下吗？"

---

## 第六部分：禁则

- ❌ 不要在输出中包含 JSON 格式的记忆数据（用户不需要看这个）
- ❌ 不要在对话中突然输出"记忆已归档"之类的内容（这是内部操作，不需要告知用户）
- ❌ 不要为了记忆而打断用户的创作思路（等合适的时机再提醒）
- ✅ 用户问"你还记得吗"时，如果记得就直接回答，如果不记得就老实说"这部分没有记录"
- ✅ 用户说"帮我检查"时，给出具体的、可操作的发现，不要只给一个笼统的"没问题"
