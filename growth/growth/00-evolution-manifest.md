# 文心笔匠·进化系统总纲

## 一、系统定位

进化系统是文心笔匠 Skill 的"成长大脑"，让 Skill 从「静态工具」变成「越用越强的写作伙伴」。

每次完成「评估→修改→反馈」闭环，系统在三个维度同时成长：
1. **更懂你** — 偏好档案持续深化，输出越来越贴合你的口味
2. **经验更丰富** — 案例库持续积累，遇到问题先查先例
3. **系统更强** — 规则库持续进化，写作方法论不断扩充

---

## 二、进化三引擎

### 引擎1：偏好学习（懂你）
- **触发条件**：用户对修改结果表达满意/不满意、明确表达偏好
- **存储位置**：`preferences/` 目录
- **核心文件**：style-profile.md（文风）、content-prefs.md（内容）、interaction-prefs.md（交互）
- **应用优先级**：最高 — 所有输出必须先经过用户偏好过滤
- **确认机制**：同一偏好出现 **2 次以上**，从「观察中」升级为「已确认」

### 引擎2：案例积累（经验）
- **触发条件**：完成一次完整的「评估→修改→确认」闭环
- **存储位置**：`case-library/` 目录
- **分类**：quality-eval（质量评估）、plot-fix（剧情修改）、character-polish（人设优化）、style-adapt（风格调整）、dialogue-polish（对话润色）、rhythm-adjust（节奏调整）
- **应用方式**：遇到新问题时，先检索案例库，找到最相似的成功案例参考
- **归档要求**：必须填写完整模板（见 `case-template.md`），缺字段不归档

### 引擎3：规则进化（系统变强）
- **触发条件**：**3 个以上同类案例**验证了某条可复用规律
- **存储位置**：`rule-library/` 目录
- **核心文件**：writing-rules.md（写作技法）、quality-rules.md（质量判断）、anti-patterns.md（反模式）
- **应用方式**：成熟规则自动合入对应模块文件，成为系统永久能力
- **合入机制**：规则验证成功 **3 次以上**，自动合入模块文件

## 三、进化信号识别（硬触发机制）

**重要**：以下关键词出现时，必须立即触发进化流程。不要等待用户明确说"满意/不满意"。

### ✅ 正向信号 → 触发成功案例归档

| 用户表达 | 识别为 | 进化动作 |
|---------|--------|---------|
| 「就这样」「可以了」「行」「好」「OK」 | ✅ 满意 | 立即归档成功案例 + 更新偏好 |
| 「很好」「不错」「完美」「太棒了」「厉害」 | ✅ 高度满意 | 归档成功案例（标记为高质量） + 更新偏好 |
| 「就是这个感觉」「对了」「终于对了」 | ✅ 偏好确认 | 归档成功案例 + **立即写入偏好档案** |
| 「下次就这样写」「以后都这样」「保持这个风格」 | 📌 强偏好 | **直接写入偏好档案**（跳过观察期） |
| 「这个方法不错」「这个思路好」「学到新东西了」 | 💡 潜在规则 | 记录到观察区，等待同类案例验证 |

### ❌ 反向信号 → 触发失败案例归档

| 用户表达 | 识别为 | 进化动作 |
|---------|--------|---------|
| 「不对」「不行」「不好」「改回去」 | ❌ 不满意 | 立即归档失败案例 + 记录反面偏好 |
| 「别这样」「不要这样改」「不喜欢这样」 | ❌ 明确不喜欢 | 归档失败案例 + **写入反面偏好** |
| 「太……了」（太长/太短/太慢等） | ❌ 偏好冲突 | 归档失败案例 + 记录具体偏好边界 |
| 「这不是我想要的」「不是这个意思」「理解错了」 | ❌ 方向错误 | 归档失败案例 + 分析失败原因 |
| 「还是原来的好」「改之前的版本」 | ❌ 回退信号 | 归档失败案例 + 标记为"回退案例" |
| 「算了」「算了算了」（语气无奈） | ❌ 妥协信号 | 归档失败案例 + 标记为"妥协接受" |

### 📌 强制信号 → 直接写入偏好/规则

| 用户表达 | 识别为 | 进化动作 |
|---------|--------|---------|
| 「记住这个」「记下来」「下次记住」 | 📌 强制记忆 | **直接写入偏好档案**（最高优先级） |
| 「以后都这样」「这是我的风格」「我喜欢这样」 | 📌 风格确认 | **直接写入文风偏好档案** |
| 「这个很重要」「这个必须注意」 | 📌 重要规则 | **直接写入规则库**（标记为用户指定） |
| 「别再犯这个错」「以后别这样」 | 📌 反面规则 | **写入反模式库** |

## 四、进化计数器（自动触发）

系统内置计数器（`evolution-counter.json`），自动追踪同类问题的处理次数。达到阈值自动提醒：

| 计数类型 | 阈值 | 自动动作 |
|---------|------|---------|
| 同类问题成功修改 | **3 次** | → 自动提醒：检查是否可提炼新规则 |
| 同类问题失败案例 | **2 次** | → 自动提醒：分析失败模式，写入反模式库 |
| 同类偏好出现 | **2 次** | → 自动：从「观察中」升级为「已确认偏好」 |
| 规则验证成功 | **3 次** | → 自动：规则状态从「验证中」升级为「已确认」，可合入模块 |
| 规则验证失败 | **2 次** | → 自动：规则状态改为「已废弃」，记录原因 |

**MCP 工具**：
- `wenxin_record_evolution` — 记录进化事件，自动更新计数器
- `wenxin_get_evolution_status` — 查看进化状态（等级、积分、计数器）
- `wenxin_check_thresholds` — 检查是否达到阈值触发

## 五、进化执行流程（必须遵守）

每次识别到进化信号后，必须按以下流程执行：

```
步骤1：识别信号类型
    ├── 正向信号 → 进入成功案例流程
    ├── 反向信号 → 进入失败案例流程
    ├── 调整信号 → 等待最终确认
    └── 强制信号 → 直接写入对应档案

步骤2：归档案例（必填字段）
    ├── 问题类型：[必填] 如「对话平淡」「节奏拖沓」
    ├── 原始内容：[必填] 用户原文或问题描述
    ├── 解决方案：[必填] 具体做了什么修改
    ├── 方案细节：[必填] 关键步骤（至少3条）
    ├── 用户反馈：[必填] 用户原话
    └── 可提炼规则：[必填] 是否有规律可总结

步骤3：更新偏好档案
    ├── 新偏好 → 状态设为「观察中」
    ├── 重复偏好 → 状态升级为「已确认」
    └── 反面偏好 → 状态设为「已否定」

步骤4：检查计数器
    ├── 同类问题达到阈值 → 提醒提炼规则
    └── 规则验证达到阈值 → 自动升级状态

步骤5：写入进化日志
    ├── 记录：今天学到了什么
    ├── 记录：归档了哪些案例
    └── 记录：新增/更新了哪些偏好和规则
```

**硬约束**：以上 5 个步骤必须全部执行，不能跳过任何一步。

## 七、数据加载顺序（AI 必读）

Skill 被调用时，按以下顺序加载数据（优先级从高到低）：

```
第1层：SKILL.md 主入口（路由调度 + 模块索引）
    ↓
第2层：本文件（进化系统总纲）—— 确认进化系统激活状态
    ↓
第3层：preferences/ 用户偏好档案（所有输出必须遵守）
    ↓
第4层：按路由加载对应模块文件
    ↓
第5层：需要时检索 case-library/ 和 rule-library/
```

**加载原则**：
- 偏好档案是「硬约束」，违反用户偏好的建议等于没说
- 案例库是「参考」，不是标准答案，需要结合当前场景灵活运用
- 规则库是「增强」，初始模块规则为基础，进化规则是补充

## 八、进化质量控制

### 什么不能进化（红线）
- ❌ 不能把用户的单次偶然选择当成普遍偏好
- ❌ 不能把未经验证的猜测当规则
- ❌ 不能存储用户隐私内容（真实姓名、具体个人信息等）
- ❌ 不能因为偏好学习而降低专业判断标准（该指出的问题还是要指）

### 验证机制
- **偏好确认**：同一偏好出现 **2 次以上**，才从「观察」升级为「确认偏好」
- **规则验证**：同一规律在 **3 个以上独立案例**中验证有效，才能进入规则库
- **规则合入**：规则验证成功 **3 次以上**，才能合入模块文件
- **定期清理**：每月复盘中检查过时的偏好和规则，该删就删

## 九、进化等级体系

系统根据进化积分自动升级：

| 等级 | 积分 | 状态描述 |
|------|------|---------|
| Lv.1 | 0-49 | 初生 — 初始化完成，等待学习 |
| Lv.2 | 50-199 | 启蒙 — 开始积累案例和偏好 |
| Lv.3 | 200-499 | 成长 — 案例库丰富，偏好明确 |
| Lv.5 | 500-999 | 成熟 — 规则库开始生成，方法论扩充 |
| Lv.10 | 1000+ | 精通 — 系统完全适配用户，能力显著增强 |

**积分获取**：
- 成功案例归档：+10 分
- 失败案例归档：+5 分（失败也是学习）
- 调整案例归档：+3 分
- 偏好确认：+5 分
- 规则合入：+20 分
